# 互动工具

- 模块定位：提供 QQ 戳一戳的发送工具，并把“机器人被戳”通知转成 Agent 可理解的事件。
- 对应代码：`yebot/runtime/interaction/`、`yebot/runtime/tools/catalog.py`、`yebot/runtime/tools/onebot.py`、`main.py`
- 所属里程碑：[M7](../roadmap.md#m7)
- 当前状态：进行中
- 最近更新时间：2026-08-07

## 职责与边界

互动模块只处理 poke 事件的结构化解析和当前会话提示。发送动作仍由 `ToolGateway` 授权，
OneBot 适配器只负责调用 `group_poke`。普通群员、群管理员和主人都可以在当前群使用，
不允许借此跨群操作。

## 结构与数据流

```text
OneBot notice/sub_type=poke
    -> parse_poke_event
    -> main.py 保存 PokeEvent 到当前事件
    -> 目标是机器人时显式唤醒主 Agent
    -> yebot_interaction_poke
    -> TargetResolver / 戳人事件发送者
    -> interaction.poke -> ToolGateway -> group_poke
```

解析器只保留发送者、目标、群号、机器人 QQ 号和安全昵称。戳到其他群员时会停止默认
Agent，避免一条旁观通知触发回复。戳到机器人时，Agent 会得到发送者信息，可以自然回复
或回戳；回戳目标不需要再次 @。

## 关键决策

- 发送工具使用细粒度权限键 `interaction.poke`，作用域为当前群，三种角色均可用。
- 工具默认遵守 YeBot 的 `observe_only` 和 `tool_dry_run`；真实发送前需关闭对应开关。
- 戳一戳不进入踢人确认门，但仍受统一额度、并发、目标保护和审计约束。
- 通知事件只在目标为机器人时唤醒 Agent，避免群内其他人的互动造成模型调用。

## 当前实现

`PokeEvent` 兼容 OneBot 顶层 `sender_id`、`user_id` 和嵌套 `sender.user_id`，并用
`target_id` 判断是否戳中机器人。`yebot_interaction_poke` 复用成员目标解析，支持 QQ 号、
群昵称、At、回复对象和自然语言指代；收到机器人被戳的事件后，空目标或“回戳/对方/他”等
指代会直接绑定本次事件的发送者。

## 验证方式

`tests/test_poke.py` 覆盖通知解析、机器人目标判断、普通目标观察和异常字段；
`tests/test_permissions.py` 覆盖三种角色的权限；`tests/test_onebot_tools.py` 覆盖真实
`group_poke` action 和 dry-run 不调用平台。

运行态验收：发送“戳一下某人”或“叶桐，戳某人”，确认日志和 QQ 事件出现 `group_poke`；
让群友戳机器人，确认 Agent 能知道发送者；让群友戳其他成员，确认机器人不自动回复。
