# 回复媒介

- 模块定位：把模型生成的内容稳定地输出为文本、语音或文字加语音，并支持按 QQ 保存偏好。
- 对应代码：`yebot/runtime/response_media/`、`main.py`
- 所属里程碑：[M7](../roadmap.md#m7)
- 当前状态：进行中
- 最近更新时间：2026-08-11

## 职责与边界

模块只决定机器人回复的媒介，不改写模型回答的语义，不参与语音识别，也不保存聊天正文。个人偏好按 QQ 号保存，跨群生效；群聊本身仍只发一条公共回复，因此以当前发言人的偏好或本条明确指令为准。

## 结构与数据流

用户消息 -> 识别“用语音/文字/双发回复”或“以后都用…” -> QQ 偏好 JSON
-> 当前事件媒介标记 -> 模型生成文本 -> 发送前转换为 Plain、Record 或两者。

没有明确指令、偏好或命中概率时使用插件配置的默认媒介，默认值为 `text`。语音合成失败时保留文本，避免请求无回应。明确要求语音时，模型提示会说明语音发送由程序自动完成；只提出媒介要求时直接生成简短确认，禁止把该请求回答成“发不了语音”。

## 关键决策

YeBot 在发送前选择媒介：明确的语音、文字或双发请求优先，已保存的 QQ 偏好其次；没有这两类信号时读取 AstrBot `provider_tts_settings.trigger_probability`，按概率选择语音，否则发送文字。YeBot 会把自己的模型结果标记为已完成转换，防止 AstrBot 全局 TTS 重复发送。

支持的自然语言包括“用语音回答”“用文字回复”“文字和语音都发”“以后都用语音回复我”“清除我的回复媒介偏好”。“以后”类表达会写入偏好；普通表达只影响本条回复。

## 当前实现

普通 YeBot 工具消息不再把显式 At 标记当作纯文本发送：发送适配层会将已解析的
`[CQ:at,qq=...]` / `[At:...]` 转成 OneBot At 消息段，未标记的 `@数字` 仍按普通文字处理。

`ResponseModeStore` 使用临时文件和原子替换保存 `text`、`voice`、`dual` 三种偏好。`parse_response_mode_intent` 只接受带明确回复动作的媒介请求，包含“我叫他发语音”这类自然表达，避免把普通的语音或文本话题误当成设置。`main.py` 在 LLM 请求前选择媒介，在发送前使用 AstrBot 已配置的 TTS 提供商生成 `Record`；双发模式先发送文本再发送语音。语音选择、提供商模型、合成异常类型只写脱敏运行标记，不写消息正文或异常响应内容。

## 验证方式

单测覆盖一次性文本/语音/双发请求、自然表达“我叫他发语音”、媒介提示契约、长期偏好、清除偏好、普通话题排除和 JSON 重启恢复。真实容器验收覆盖文本、语音、双发、长期偏好和 TTS 失败回退文本；当前已用固定短文本确认生产 MiMo 提供商可生成 MP3，QQ 人工验收仍需实际发送一条请求。

`tests/test_response_media_selection.py` covers reading the provider probability,
automatic voice selection, and explicit or saved mode precedence.

## 待扩展项

可增加语速、音色和仅私聊语音等个人偏好；当前复用 AstrBot 已选中的 TTS 提供商与音色。
