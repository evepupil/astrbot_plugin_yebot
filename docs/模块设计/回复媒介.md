# 回复媒介

- 模块定位：把模型生成的内容稳定地输出为文本、语音或文字加语音，并支持按 QQ 保存偏好。
- 对应代码：`yebot/runtime/response_media/`、`main.py`
- 所属里程碑：[M7](../roadmap.md#m7)
- 当前状态：进行中
- 最近更新时间：2026-08-04

## 职责与边界

模块只决定机器人回复的媒介，不改写模型回答的语义，不参与语音识别，也不保存聊天正文。个人偏好按 QQ 号保存，跨群生效；群聊本身仍只发一条公共回复，因此以当前发言人的偏好或本条明确指令为准。

## 结构与数据流

用户消息 -> 识别“用语音/文字/双发回复”或“以后都用…” -> QQ 偏好 JSON
-> 当前事件媒介标记 -> 模型生成文本 -> 发送前转换为 Plain、Record 或两者。

没有明确指令或偏好时使用插件配置的默认媒介，默认值为 `text`。语音合成失败时保留文本，避免请求无回应。

## 关键决策

AstrBot 原生 TTS 使用全局概率，无法按单条消息稳定控制。YeBot 在发送前自行选择媒介，并将自己的模型结果标记为已完成转换，防止全局随机 TTS 覆盖选择。生产配置将原生 TTS 的概率设为零，TTS 提供商仍保持启用，供 YeBot 的明确语音请求调用。

支持的自然语言包括“用语音回答”“用文字回复”“文字和语音都发”“以后都用语音回复我”“清除我的回复媒介偏好”。“以后”类表达会写入偏好；普通表达只影响本条回复。

## 当前实现

`ResponseModeStore` 使用临时文件和原子替换保存 `text`、`voice`、`dual` 三种偏好。`parse_response_mode_intent` 只接受带明确回复动作的媒介请求，避免把普通的语音或文本话题误当成设置。`main.py` 在 LLM 请求前选择媒介，在发送前使用 AstrBot 已配置的 TTS 提供商生成 `Record`；双发模式先发送文本再发送语音。

## 验证方式

单测覆盖一次性文本/语音/双发请求、长期偏好、清除偏好、普通话题排除和 JSON 重启恢复。真实容器验收覆盖文本、语音、双发、长期偏好和 TTS 失败回退文本。

## 待扩展项

可增加语速、音色和仅私聊语音等个人偏好；当前复用 AstrBot 已选中的 TTS 提供商与音色。
