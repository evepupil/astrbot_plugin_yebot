# 工具包与后台任务

- 模块定位：在权限和审计基础上提供查询、提醒、文件/网页任务、可暂停后台作业和低成本只读查询。
- 对应代码：`yebot/runtime/tools/`、`yebot/runtime/jobs/`、`yebot/runtime/forwarding/`
- 所属里程碑：[M7](../roadmap.md#m7)
- 当前状态：进行中
- 最近更新时间：2026-08-05

## 职责与边界

工具包只承载清晰、可测试的能力；模型排行榜属于固定来源的只读查询；后台任务必须有所有者、作用域、状态和取消方式。

## 结构与数据流

提醒请求 -> 主人提醒意图解析（可解析时直达） -> M4/M6 网关 -> 任务记录
-> 调度/执行 -> QQ 通知。

转发对话请求 -> 主 Agent 生成对话草稿 -> 节点校验与昵称渲染 -> M4/M6 网关
-> OneBot 合并转发。普通用户仍由主 Agent 选择提醒工具，所有执行都经过网关。

撤回请求 -> 当前消息唯一引用，或最近消息候选查询 -> M4/M6 网关 -> `get_msg` 校验当前群 -> `delete_msg`。

AstrBot active-agent 定时任务 -> Cron `session`/`sender_id` 元数据 -> `BackgroundToolContext`（群号、执行者身份、运行 ID、action 客户端） -> M4/M6 网关 -> OneBot。普通延时提醒仍由 YeBot `JobScheduler` 读取持久化任务并执行。

## 关键决策

文件和网页工具默认只读并限制在配置根目录/公开 HTTP(S)；OneBot 只读 action 使用短时共享缓存，写操作成功后清理受影响群的数据；YeBot 提醒任务有创建者和群作用域，创建者只用于审计，当前群内所有成员都可查看、取消、暂停或恢复该群任务。AstrBot 原生 `future_task` 任务也通过 YeBot 兼容层按平台会话和群号共享列表、编辑与删除；私聊任务和无法解析群号的任务仍只允许创建者管理。不同群的任务严格隔离，避免跨群干预。撤回仅主人和当前群管理员可用，回复目标优先；非回复场景由模型先读取最近消息并按内容选择。候选消息 ID 只在当前事件有效，工具重新读取消息确认群作用域后才执行；它可用于群员消息和机器人自己的消息。转发对话仅主人可用，目标可通过 @、回复、人名、QQ 号或指代词交给[目标解析](目标解析.md)，节点昵称由工具从当前群昵称渲染，不使用目标的真实 QQ 号。重试使用次数上限和指数退避，避免群消息刷屏。

## 当前实现

转发场景的 `speaker=target` 和已解析目标昵称都会归一为当前群目标昵称；模型可以直接复用目标昵称生成草稿，工具层仍负责目标校验、纯文本边界和 OneBot 节点构造。

定时 Agent 没有标准 QQ 原始事件时，工具层只接受显式的 `BackgroundToolContext`。群号来自任务会话或可信任务字段，执行者来自任务创建者字段；群管理员角色通过 OneBot 的非缓存查询确认，查询失败按普通群员处理。平台 action 客户端从当前 Cron 事件携带的 AstrBot `Context` 和平台 ID 恢复，事件对象本身仍只作为临时上下文传递；最近发言人解析使用配置的真实机器人 QQ 号排除机器人自身消息。

已实现 `reminder.create/list/cancel/pause/resume`，JSON 存储采用临时文件加原子替换。`JobScheduler` 提供到期执行、暂停/恢复、取消、失败重试和指数退避；`list` 会返回当前群全部任务及创建者、内容和状态，当前群任意成员都能管理，以便及时制止刷屏任务。插件加载时还会适配 AstrBot 原生 `future_task` 工具的群任务权限，让同群成员可以列出、编辑和删除原生 Cron 任务；该兼容层只改群聊任务，私聊仍按创建者隔离。`runtime/jobs/intent.py` 解析带相对时间的中文提醒命令，支持秒、分钟、小时、天、周和单个 @ 目标，也会保留非 @ 的目标文本。主人命令在 LLM 请求前直达 `reminder.create`，名字或指代词会先由[目标解析](目标解析.md)验证成唯一成员，再写入到期消息的 QQ @；缺时间、内容或唯一目标时直接提示补充，避免被聊天人设拦截。

`message.get_recent_for_recall` 使用 `get_group_msg_history` 返回最近的消息 ID、发送者和安全截断的内容，排除当前撤回指令；`message.recall` 从当前唯一回复段或这次候选查询取得 `message_id`，主 Agent 不可编造。工具层使用 `get_msg` 检查目标消息归属当前群后调用 `delete_msg`。它和转发对话都受额度、审计、幂等和 dry-run 约束。`message.forward_scene` 接收模型生成的 3 到 12 条 `speaker/content` 草稿；`speaker=target` 会被替换为当前群中已解析成员的昵称，其余 speaker 也按文本原样作为节点昵称（工具会剥离误加的 `（虚构）` 后缀）。节点只允许纯文本，拒绝 CQ 码和任意原始 OneBot 段；写入时调用 `send_group_forward_msg`。OneBot 运行适配器还提供 `file.read`、`web.fetch` 和 `model.ratings`；文件路径不能越过配置根目录，网页请求拒绝本地和私网地址，模型排行榜只读取 Codex Radar 固定 JSON 接口并在插件内短时缓存。`OneBotReadCache` 还对成员列表、群历史、引用消息和图片信息做短时缓存；撤回群归属与目标角色校验通过 `call_uncached` 保持实时。后台循环在首次工具请求后启动，插件终止时取消。

Codex heartbeat `yebot` 作为运维侧后台任务，每 30 分钟检查上一个窗口以来的 AstrBot/NapCat 容器日志。它只提取错误类型、固定启动和连接标记、次数、哈希及聚合状态，不保存消息正文、提示词或凭据；发现有明确技术根因的问题时，要求补回归单测、通过发布门禁、提交推送并按需同步 WSL 和重启 AstrBot。涉及业务取舍、权限、生产数据、真实 QQ 验收或无法确认根因的问题，按 `docs/review/` 的单次记录和 `_剩余问题.md` 增量规则停留待决策状态。

Token 计算工具属于同步只读工具：`token.calculate` 在网关内执行 TokenCal 固定公式，沿用页面默认价格和国产 / 国外两个场景。总 Token 数以百万 M 传入，结果带有来源、综合单价和预计费用。

## 验证方式

单测覆盖提醒意图解析、YeBot 和 AstrBot 原生 Cron 的群内共享/跨群隔离、转发对话节点渲染与边界、主人权限、OneBot 合并转发 payload、消息撤回的角色、引用或候选目标、当前群验证和 `delete_msg` action、任务创建、取消、暂停/恢复、重试退避、最终失败、JSON 重启恢复、文件根目录保护和私网 URL 拒绝；真实容器还需验证原生 `future_task` 列表能看到同群他人任务，并能删除其中一条，同时确认私聊任务仍不可被他人管理。

## 待扩展项

增加 cron/重复规则、队列化执行和任务进度消息；当前任务按群隔离、在群内共享管理。
