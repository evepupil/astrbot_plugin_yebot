# 工具网关

- 模块定位：为所有工具提供统一声明、参数校验、权限检查、超时和错误包装。
- 对应代码：`yebot/runtime/tools/`
- 所属里程碑：[M4](../roadmap.md#m4)
- 当前状态：进行中
- 最近更新时间：2026-08-01

## 职责与边界

工具网关是唯一允许工具执行的入口。Agent 不直接持有 QQ、文件系统或网络客户端；平台适配器只负责把已授权的工具声明注册到网关。

## 结构与数据流

工具目录 -> 工具查找 -> 身份/作用域检查 -> 参数校验 -> 超时执行 -> 统一结果。

工具注册与执行分开：`ToolDefinition` 只保存名称、用途、权限键、参数 schema、风险和超时；`ToolRegistry` 保存声明与异步 handler；`ToolGateway` 是唯一调用入口。执行上下文包含身份、有效目标群和请求 ID，handler 不需要重新推断调用者身份。

## 关键决策

每个工具必须声明名称、用途、权限键、参数 schema、风险等级和超时。权限键可以按工具拆分，例如 `group.member.kick` 与 `group.member.mute`；工具也可以通过 `permission_policy` 提供独立角色覆盖。风险字段先用于声明，二次确认由 M6 统一接管。

## 当前实现

已实现：`ToolDefinition`、`ParameterSpec`、`ToolRegistry` 和 `ToolGateway`。网关会拒绝未知工具、未知权限、角色不足、越过当前群和缺少群号的请求；参数只接受声明的 JSON-like 类型，不做隐式转换；handler 受单工具超时限制，异常只返回稳定错误类型，不泄漏异常正文。

`catalog.py` 已声明 `group.kick_member`、`group.mute_member`、`group.unmute_member`、`group.get_members` 和 `message.send`。这些声明等待后续平台适配器注册实际执行器，当前不会改变只观察运行模式。

## 验证方式

`tests/test_tools.py` 覆盖工具注册、重复名称、工具发现、参数错误、细粒度权限、群作用域、缺少群号、超时和异常包装。真实 QQ action handler、目标成员层级检查、二次确认和幂等控制分别由平台接入、M6 和后续工具包负责。

## 待扩展项

增加插件式工具发现、按群启停、目标成员层级检查、二次确认、幂等键和沙箱执行。
