# 平台接入

- 模块定位：定义 AstrBot 与 OneBot/AIOCQHTTP 的事件接入和验收边界。
- 对应代码：`main.py`、`yebot/runtime/observer.py`
- 所属里程碑：[M1](../roadmap.md#m1)
- 当前状态：进行中
- 最近更新时间：2026-08-05

## 职责与边界

只负责平台事件到插件内部摘要的转换。消息发送、模型调用和工具执行属于后续模块。

## 结构与数据流

AstrBot 先按 `AIOCQHTTP` 和 `GROUP_MESSAGE` 过滤，再由运行时检查原始 OneBot 事件的 `post_type` 与 `message_type`。`message`、`sender`、`group_id` 只用于当次解析。

## 关键决策

通知和请求事件不进入消息观察逻辑。当前适配器可能把带群号的通知包装成群消息，因此必须再次检查原始 `post_type == message`。

## 当前实现

入口已经注册 AIOCQHTTP 群消息过滤器，并调用 `observe_event` 生成脱敏摘要。机器人 QQ 号优先从 AstrBot 事件的 `event.get_self_id()` 获取，插件配置中的 `bot_qq_id` 只作为兼容旧版本和测试的备用值。入口和运行时适配器同时支持 AstrBot 插件包相对导入与本地直接导入，容器实际加载已验证通过。

当 QQ 引用段位于当前文本前面时，平台唤醒阶段可能没有把后面的配置唤醒词识别为消息开头。`yebot/runtime/addressing.py` 只检查引用段之后的当前文本，匹配配置中的唤醒词后由 YeBot 恢复 `is_at_or_wake_command`，不放宽普通群消息的唤醒规则，也不改变后续权限判断。

`yebot/runtime/replies.py` 解析 AstrBot 的 `Reply` 组件和原始 OneBot
`reply` 段。引用段没有正文时，通过 `get_msg` 按消息 ID 查询原消息，并把文本、组件占位符和消息 ID 注入当前 Agent 请求。结果按事件缓存，限制引用数量和总长度，不保留图片 URL、文件路径等原始字段。

## 验证方式

用纯 Python 单测覆盖消息、通知、请求三类输入；运行中的容器补做私聊往返和群聊 @ 验收。

## 待扩展项
