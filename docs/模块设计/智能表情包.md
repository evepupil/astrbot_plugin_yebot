# 智能表情包

- 模块定位：把群消息中的图片交给主 Agent 识图，由 Agent 判断是否收藏，并按语义检索和发送已收藏图片。
- 对应代码：`yebot/runtime/stickers/`、`yebot/runtime/tools/catalog.py`、`yebot/runtime/tools/onebot.py`、`main.py`
- 所属里程碑：[M7](../roadmap.md#m7)
- 当前状态：进行中
- 最近更新时间：2026-08-02

## 职责与边界

表情模块只处理图片，不保存完整消息正文。模型负责识别图片和决定是否值得收藏；程序负责读取当前事件图片、去重、持久化、群范围隔离和 OneBot 发送。表情库默认按群隔离，普通群员也可以使用当前群的搜索和发送能力，所有调用仍经过 M4 工具网关。

## 结构与数据流

```text
AstrBot Image 消息
    -> 主 Agent 识图
    -> sticker.consider(收藏决定、含义、标签)
    -> StickerService -> StickerStore(index.json + files/<sha256>)

自然语言发表情
    -> sticker.search(语境)
    -> sticker.send(sticker_id)
    -> OneBot send_group_msg(image segment)
```

图片文件放在 `data/yebot_stickers`，该目录属于 AstrBot/NapCat 共同挂载的 `data`，发送时使用容器内共享的 `file:///AstrBot/data/...` URI。元数据采用原子 JSON 替换，图片按 SHA-256 内容寻址，重复图片不会重复写入。

## 关键决策

- 不在插件内重复调用视觉模型。AstrBot 已把图片组件转换为模型可见的图片内容，YeBot 通过系统提示要求模型在识图后提交收藏判断。
- `sticker.consider` 的 `should_collect=false` 只记录判断结果，不落盘；收藏时必须提供含义，标签用于后续检索。
- `sticker.search` 只返回当前群的表情元数据和稳定 ID，不跨群暴露图片来源；`sticker.send` 只允许发送当前群的 ID。
- `tool_dry_run=true` 时发送只返回 OneBot 预览，不增加使用次数；真实发送成功后才增加使用次数。
- 当前版本优先支持 `image` 图片段；QQ 原生 `mface` 仍保留在平台消息里，待后续补充可复用资源解析。

## 当前实现

`StickerStore` 提供内容去重、JSON 原子持久化、群内搜索和使用计数。`StickerService` 从 AstrBot `Image` 组件读取本地文件或 base64，清理模型提供的标签并返回脱敏元数据。工具目录增加 `sticker.consider`、`sticker.search`、`sticker.send`，三者分别映射到收藏、检索和 OneBot 图片发送。主 Agent 提示已加入自动识图收藏和自然语言发表情规则。

## 验证方式

`tests/test_stickers.py` 覆盖去重、重启恢复、拒绝收藏、语义搜索和真实 OneBot 图片段发送；全量 pytest、Ruff 和 strict mypy 作为提交门禁。容器验收需要发送一张图片，确认模型先完成识图后选择收藏，随后用自然语言要求发表情，检查 QQ 收到图片。
