# 模型排行榜

- 模块定位：读取 Codex Radar 的公开模型社区评分，为 YeBot 提供结构化的模型排行和历史评分查询。
- 对应代码：`yebot/runtime/model_ratings/`、`yebot/runtime/tools/catalog.py`、`yebot/runtime/tools/onebot.py`、`main.py`
- 所属里程碑：[M7](../roadmap.md#m7)
- 当前状态：已完成
- 最近更新时间：2026-08-03

## 职责与边界

模块只读取固定的 Codex Radar 公共接口，不抓取整页 HTML，不提交评分，也不接受模型传入的任意 URL。它只返回社区滚动 24 小时评分、投票数和可选的历史数据；模型推荐仍由 Agent 根据用户问题解释，排行榜数据本身不代表 YeBot 的绝对结论。

## 结构与数据流

`yebot_model_ratings` -> `ToolGateway` 权限与参数校验 -> `ModelRatingsClient` -> 固定接口 `https://codexradar.com/api/model-ratings?view=public&history=14` -> 响应校验 -> 按评分降序筛选 -> Agent 整理回复。

`ModelRatingsClient` 在插件生命周期内缓存完整快照，默认缓存 300 秒；每次请求最多等待 8 秒，响应超过 250 KB 会拒绝。查询支持模型 ID、显示名或系列名的大小写不敏感包含匹配，默认返回前 10 个，最多 20 个；历史数据最多返回最近 14 天，并且只保留当前返回模型。

## 关键决策

- 使用站点已经调用的公开 JSON 接口，避免依赖前端 DOM、脚本顺序和页面文案。
- 工具权限为 `model.ratings.read`，所有角色均可全局只读查询，不要求当前群，也不调用 OneBot 写操作。
- 网络客户端与工具网关分离：客户端负责下载、缓存和数据模型；网关负责权限、参数、超时和统一错误包装。
- 返回源站更新时间、统计窗口和来源标记，回复时可以区分“当前滚动 24 小时数据”和历史数据。
- 只保留固定来源和有限字段，避免把站点原始响应直接塞进 Agent 上下文。

## 当前实现

`models.py` 校验 `ok`、更新时间、统计窗口、模型标识、评分范围和投票数；`client.py` 使用标准库 HTTP 客户端，设置 User-Agent、响应大小上限和并发缓存锁。查询结果包含 `rank`、模型名称、系列、均分和投票数；传入 `include_history=true` 时附带最近若干天的同模型数据。

`main.py` 暴露 `yebot_model_ratings`，自然语言规则会把“模型排行”“社区体感分”“档位对比”和“历史评分”路由到该工具。`model_ratings_enabled` 可关闭工具，超时和缓存时间可配置；默认值分别为启用、8 秒和 300 秒。

## 验证方式

- `tests/test_model_ratings.py`：覆盖响应校验、评分排序、系列筛选、数量限制、历史裁剪和缓存复用。
- `tests/test_onebot_tools.py`：覆盖工具注册、普通成员读取权限和无 OneBot 写操作。
- 提交前运行 pytest、Ruff、strict mypy、配置 JSON 解析和 `git diff --check`。

## 待扩展项

如果 Codex Radar 后续公开正式版本化 API，可把响应版本和接口地址迁移到独立配置；如果需要接入站点其他雷达，应新建独立工具和数据模型，避免把不同统计口径混成一个排行。
