# 生图

- 模块定位：把用户明确提出的画图请求转换成 GPT2IMAGE 图片，并控制普通用户每日次数。
- 对应代码：`yebot/runtime/image_generation/`、`main.py`
- 所属里程碑：[M7](../roadmap.md#m7)
- 当前状态：进行中
- 最近更新时间：2026-08-03

## 职责与边界

模块只处理明确的文生图请求、远程 API 调用、图片消息发送和每日配额。它不参与普通聊天的低频概率策略，也不保存用户提示词。主人由插件配置的 `owner_qq_ids` 和 AstrBot `admins_id` 识别，普通用户按 QQ 号跨群共享每日 3 次机会。

## 结构与数据流

```text
群聊消息 -> @ 机器人门禁 -> 意图识别 -> 配额原子预占 -> 回复“开始画了”
私聊消息 ----------------------^（私聊不需要 @）
                                      |
                                      v
                              后台调用 /v1/images/generations
                                      |
                                      v
                         引用原消息 + 图片 / 失败提示
```

意图识别支持以“画、绘制、生成一张、生图、做图”等动词开头的中文请求，也支持常见英文 `draw` / `generate an image` 请求。配额在远程调用前预占，避免并发请求超出上限；API 失败不会返还本次机会。

## 关键决策

- API 使用 `POST /v1/images/generations`，固定请求单张 `1024x1024` 图片并要求 `response_format=url`；客户端同时兼容服务端返回的 `b64_json`。
- API key 从插件 `image_api_key` 或 `GPT2IMAGE_API_KEY` 环境变量读取，源码和文档不保存真实密钥。
- 配额文件只记录 QQ 号、日期和计数，不记录提示词；写入采用临时文件加原子替换。进程内用异步锁保证同一时刻只有一个请求成功预占最后一次机会。
- 生图属于用户明确请求，使用独立的 @ 门禁：群聊必须 @ 机器人，私聊不需要 @；它不受普通群消息的冷却、概率和 `observe_only` 低频观察策略影响，可以用 `image_generation_enabled` 单独关闭。
- 初始响应只发送“开始画了”；完成响应使用 AstrBot `Reply` 消息段引用原始消息，再发送图片。

## 当前实现

`intent.py` 提供纯函数意图识别和群聊 @ 门禁；`quota.py` 提供重启可恢复的每日计数；`client.py` 使用 Python 标准库异步线程调用外部 API，避免增加插件运行依赖。`main.py` 同时注册 OneBot 群聊和私聊入口，普通用户没有次数时直接回复“没了”。

配置项包括 API 根地址、模型、超时、每日上限和配额文件路径。默认 key 为空，部署时通过 AstrBot 配置或环境变量注入。

## 验证方式

`tests/test_image_generation.py` 覆盖中文/英文意图、群聊 @ 门禁、无关问题过滤、跨重启配额、跨日重置、主人豁免、并发预占、请求体、URL/base64 响应和 API 错误。真实容器还需用普通成员在群里 @ 机器人发送四次画图请求，确认前三次出图、第四次回复“没了”，再确认未 @ 不会消耗次数，私聊无需 @。

## 待扩展项

增加按群独立上限、管理员查询剩余次数、失败返还策略和图片落盘转发。当前默认只发送 API 返回的 URL 或 base64，避免插件额外管理图片文件。

## 改动历史

- 2026-08-03：新增直接生图入口、每日普通用户 3 次配额、主人豁免和原消息引用回复。
- 2026-08-03：增加群聊 @ 机器人门禁，避免普通“画画”聊天误触发生图。
