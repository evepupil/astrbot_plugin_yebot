# 确认、审计与限额

- 模块定位：阻止高风险动作被模型直接执行，并留下最小必要的可追溯记录。
- 对应代码：`yebot/runtime/guardrails/`、`yebot/runtime/tools/gateway.py`
- 所属里程碑：[M6](../roadmap.md#m6)
- 当前状态：进行中
- 最近更新时间：2026-08-03

## 职责与边界

负责二次确认、幂等键、审计事件、频率/并发/步骤额度和超时停止。

## 结构与数据流

计划动作 -> 权限/目标保护 -> 额度和并发检查 -> 踢人请求确认或其他动作直接执行 -> 工具网关 -> 结果审计。

## 关键决策

只有 `group.kick_member` 需要二次确认；确认绑定用户、群、完整参数摘要和过期时间，并且只能消费一次。禁言、解禁、发消息和消息撤回不弹确认，仍受每日额度、并发上限、目标保护和审计约束。消息撤回会额外在工具层校验引用消息属于当前群。审计不保存完整聊天内容和秘密。

## 当前实现

`GuardrailManager` 提供一次性确认编号、过期和串用防护、目标成员保护、每日动作额度、踢人独立额度、并发上限、幂等结果缓存和失败审计。`message.recall` 使用消息 ID 参与幂等键，引用目标或当前事件候选均由工具层先校验当前群；`ToolGateway.confirm` 是唯一确认执行入口。默认保护主人和机器人账号，动作失败后不会自动重复执行。

## 验证方式

单测覆盖确认过期、确认串用、重复请求、限额耗尽、并发限制、目标保护、执行异常和审计脱敏；真实容器还需确认编号交互和 OneBot action 结果。

## 待扩展项

增加管理员审批、审计导出和异常告警；跨重启的待确认状态仍保持关闭，避免旧确认编号恢复后产生副作用。

## 改动历史

- 2026-07-31：建立确认和审计边界。
- 2026-08-02：实现踢人确认、幂等、额度、并发、目标保护和脱敏审计。
- 2026-08-03：消息撤回接入既有额度、并发、幂等与审计，保持无需二次确认。
- 2026-08-03：非回复撤回引入当前事件候选绑定，阻止模型使用未查询或跨消息的 ID。
