# 系统运维工具

- 模块定位：向主人提供运行环境和当前进程的只读运维数据。
- 对应代码：`yebot/runtime/system_info/`、`yebot/runtime/tools/catalog.py`、`yebot/runtime/tools/onebot.py`、`main.py`
- 所属里程碑：[M7](../roadmap.md#m7)
- 当前状态：进行中
- 最近更新时间：2026-08-06

## 职责与边界

模块提供 CPU、内存、系统运行时间、YeBot 进程运行时间、进程 RSS 和当前进程已观察到的 Token usage 查询。工具只读，不调用 OneBot 写操作，也不读取消息正文、凭据或环境变量。权限只开放给主人，`system_info_enabled` 可以整体关闭。

采集结果对应 AstrBot 实际运行环境。AstrBot 在容器中运行时，CPU、内存和进程信息表示容器内可见的运行环境；系统运行时间和进程运行时间分开返回，避免把宿主机启动时间误报成机器人运行时间。

## 结构与数据流

```text
AstrBot LLMResponse.usage -> TokenUsageTracker -> system.token_stats
                                          \
                                           -> ToolGateway -> owner-only Agent tool
SystemInfoCollector ---------------------> system.info
```

`system.info` 由 `SystemInfoCollector` 使用 Python 标准库读取 `/proc` 或 Windows API，并对 CPU 做短间隔采样。`system.token_stats` 由 `main.py` 的 `on_llm_response` 钩子接收 AstrBot 已报告的 `LLMResponse.usage`，汇总普通输入、缓存输入、输出和总量。

## 关键决策

- 只使用 Python 标准库，不增加 `psutil` 依赖，兼容当前 Windows 源码环境和 Linux 容器运行环境。
- 系统信息和 Token usage 使用独立工具与独立权限键，便于后续按风险或配置单独关闭。
- `observe_only=true` 时仍允许主人查询这两个无副作用的诊断工具；其他 Agent 工具继续被观察模式拦截。
- Token 统计只累加已报告的 usage；没有 usage 的响应只计入 `responses_without_usage`，不会把请求次数、估算值或默认价格当成 Token。
- Token 统计暂存于当前 YeBot 进程，重启后从零开始。跨重启历史统计应复用 AstrBot 的 `provider_stats`，后续再设计版本兼容的只读适配层。
- 当前 `on_llm_response` hook 收到的是 AstrBot 交给插件的响应 usage；多轮 tool-loop 的完整累计值由 AstrBot 内部 `provider_stats` 保存，因此这里的 `total_tokens` 是插件已观察到的运行值，不作为完整账单口径。
- CPU 利用率无法取得两个有效采样点时返回 `null`，同时保留可用的逻辑核心数和 load average。

## 当前实现

`collector.py` 返回 host、cpu、memory、system 和 process 五组结构化字段，包含原始秒数/字节数和便于 Agent 复述的显示值。内存和 RSS 同时返回原始字节数与二进制单位显示值。Linux 使用 `/proc/stat`、`/proc/meminfo`、`/proc/uptime` 和 `/proc/self/status`；Windows 使用 `GetSystemTimes`、`GlobalMemoryStatusEx`、`GetTickCount64` 和 `GetProcessMemoryInfo`，不可用的平台字段返回 `null`。

`usage.py` 接受 AstrBot `TokenUsage` 形状或同名映射，输出 `input_other_tokens`、`input_cached_tokens`、`input_tokens`、`output_tokens`、`total_tokens` 及 usage 响应计数。`catalog.py` 声明 `system.info` 与 `system.token_stats`，并列出观察模式下允许的诊断工具；`permissions.py` 限制主人角色，`onebot.py` 和 `main.py` 完成网关、function tool 和 Agent 提示词接入。

## 验证方式

- `tests/test_system_info.py` 覆盖 Token 汇总、缺失 usage、CPU 差分、内存计算、系统/进程运行时间和格式化。
- `tests/test_onebot_tools.py` 覆盖系统工具主人权限、Token 返回值和无 OneBot action 调用。
- `tests/test_permissions.py` 覆盖普通成员、群管理员和主人三种角色的权限矩阵。
- 提交前运行 pytest、Ruff、strict mypy、配置 JSON 解析和 `git diff --check`。
- 容器重载后用主人身份自然语言查询一次 CPU/内存/运行时间，再查询已观察到的 Token usage；没有 usage 时应明确显示 unavailable。

## 待扩展项

增加基于 AstrBot `provider_stats` 的跨重启/按时间范围 Token 统计，补充 cgroup CPU/内存限制视图，以及按 provider/model 的聚合；扩展前先固定数据来源和隐私边界。
