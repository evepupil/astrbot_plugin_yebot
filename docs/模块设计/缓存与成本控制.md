# 缓存与成本控制

- 模块定位：在 YeBot 进程内复用短时只读数据和图片识图结果，减少 OneBot 请求与重复模型调用。
- 对应代码：`yebot/runtime/cache.py`、`yebot/runtime/tools/read_cache.py`、`yebot/runtime/stickers/caption_cache.py`、`main.py`
- 所属里程碑：[M7](../roadmap.md#m7)
- 当前状态：进行中
- 最近更新时间：2026-08-04

## 职责与边界

缓存只保存当前进程中的短时数据，重启后自动清空，不替代 SQLite 记忆、表情库或 AstrBot 的上下文管理。只读 action 才能进入 OneBot 缓存；写操作成功后清理受影响群的数据。涉及权限、目标群和目标角色的写操作仍使用实时 OneBot 查询。

## 结构与数据流

```text
YeBot 事件
  -> 共享 OneBotActionClient
  -> OneBotReadCache
     -> 命中：直接返回
     -> 未命中：同 key 并发合并为一次 OneBot 请求
  -> 过期/写操作：删除对应缓存

表情图片
  -> 本地文件内容或 data URL 指纹
  -> provider + model + 提示词版本
  -> StickerCaptionCache
  -> 文本模型才发起图片描述请求
```

## 关键决策

- `get_group_member_list` 和 `get_group_member_info` 缓存 30 秒，`get_group_msg_history` 缓存 5 秒，`get_msg` 和 `get_image` 缓存 60 秒。
- 缓存容量有上限，过期结果和失败请求不会长期保留；相同 key 的并发请求共享一个 loader，避免事件同时到达时重复打 OneBot 或模型。
- `message.recall` 的群归属校验与群管理目标角色校验通过 `call_uncached` 实时读取，缓存只服务查询和前置解析。
- 表情描述缓存使用图片内容指纹、provider、模型和提示词版本作为 key，成功结果保留 24 小时，空描述不写入缓存。
- 当前 provider 已声明支持图片时，表情分类直接把图片交给受限 Agent，跳过额外 caption 请求；切换到文本模型后才使用配置的 caption provider。
- 缓存只记录脱敏计数，插件终止时输出命中、未命中和并发合并数量，不记录 QQ 消息、图片内容或 provider 密钥。

## 当前实现

`AsyncTTLCache` 提供 TTL、容量上限、并发合并和统计计数。`OneBotReadCache` 绑定 action 到 TTL，并在群写操作后清理相关条目。`YeBot` 在实例生命周期内共享同一个 OneBot 缓存，因此每个事件重新包装 action client 也不会丢失缓存。`StickerCaptionCache` 在调用 text-only caption provider 前生成图片指纹，并复用成功描述。

## 验证方式

`tests/test_cache.py` 验证 TTL、并发合并和失败不缓存；`tests/test_read_cache.py` 验证跨 client 命中、实时读取和写操作失效；`tests/test_sticker_caption_cache.py` 验证本地文件/data URL 指纹一致、provider/model 隔离和空结果不缓存。完整门禁仍为 pytest、Ruff 和严格 Mypy。

## 待扩展项

- 将命中率接入现有脱敏运行指标，按 action 分类观察实际节省效果。
- 当 OneBot 查询量继续增长时，再按群或 action 分离容量，避免大型历史响应占用过多内存。

## 改动历史

- 2026-08-04：新增有界异步 TTL 缓存、OneBot 只读 action 缓存和表情图片描述缓存；当前模型支持图片时跳过重复 caption 请求。
