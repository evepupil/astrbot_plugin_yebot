# 记忆系统

- 模块定位：为 YeBot 提供范围明确、可删除、可审计的长期事实与偏好记忆。
- 对应代码：`yebot/runtime/memory/`、`yebot/runtime/tools/catalog.py`、`yebot/runtime/tools/onebot.py`、`main.py`
- 所属里程碑：[M9](../roadmap.md#m9)
- 当前状态：进行中
- 最近更新时间：2026-08-02

## 职责与边界

记忆模块只保存用户明确要求记录的事实、偏好、规则和有限摘要。模块负责记忆的范围检查、内容安全、过期、替换、软删除和召回排序。

AstrBot 的当前会话上下文仍由 AstrBot 负责。提醒、待确认动作、额度、审计事件和表情图片继续使用各自的存储模块。记忆模块不保存完整群聊、原始 OneBot 事件、密码、Token、Cookie、私钥或其他凭据。

## 结构与数据流

```text
当前消息
  -> parse_identity
  -> MemoryService.recall（私聊：用户/机器人范围；群聊：当前群范围）
  -> render_memory_context（有限、不可信参考资料）
  -> AstrBot ProviderRequest

用户明确要求记住/忘记
  -> AstrBot function tool
  -> YeBot Agent 编排
  -> ToolGateway 身份与权限检查
  -> MemoryService
  -> SQLiteMemoryStore
```

持久化文件默认是 `data/yebot_memory.db`。SQLite 每次操作使用短连接和事务，启用 WAL，适合插件的小规模并发访问。数据库保存结构化记录，不保存原始消息正文。

## 关键决策

### 范围模型

- `user`：以 QQ 号绑定，只在私聊中对本人可见。
- `group`：以群号绑定，当前群成员可以读取；写入要求群管理员或主人。
- `bot`：保存机器人级规则，只允许主人读写。

用户记忆和机器人级记忆不会注入群聊。所有自动召回都会先根据当前身份和私聊/群聊边界过滤范围。

### 写入模型

每条记录包含 `topic`、`kind`、`content`、标签、置信度、来源请求 ID、创建/更新时间和可选过期时间。相同范围、主体和主题再次写入时，旧记录标记为 `superseded`，新记录保持独立 ID，便于追溯。

记忆内容经过长度限制和敏感词检查。普通闲聊不触发持久化，模型只能在用户表达“记住”“以后都这样”等明确意图时调用写入工具。

### 召回模型

自动召回最多注入 4 条当前可见的相关记录。首版采用主题、正文和标签关键词评分，中文查询使用连续词组和双字片段，不引入额外分词依赖。没有匹配时不会把无关旧记忆塞进普通请求。

注入模型的内容会明确标记为用户提供的参考资料。它不能改变当前指令、身份权限、工具参数或安全策略。

### 删除模型

`memory.forget` 只做软删除，记录状态变为 `forgotten`，历史行保留。已忘记和已替换的记录不参与普通召回。

## 当前实现

- `models.py`：范围、类型、状态和不可变记忆记录。
- `store.py`：SQLite schema、索引、事务替换、软删除和重启恢复。
- `service.py`：范围授权、敏感内容拒绝、过期、版本替换和关键词召回。
- `renderer.py`：将召回结果限制长度并标记为不可信参考资料。
- `catalog.py`：注册 `memory.remember`、`memory.recall`、`memory.forget` 三个网关工具。
- `main.py`：在 `on_llm_request` 自动召回，并提供自然语言可调用的记住、回忆、忘记入口。
- `main.py`：对明确的“记住/记一下/以后都这样”请求先通过权限网关执行一次写入，再追加高优先级结果提示，避免聊天人设跳过记忆工具；群聊仍只允许明确的群范围记忆。
- `_conf_schema.json`：提供自动召回开关和数据库路径配置。

## 验证方式

核心单测覆盖：SQLite 重启恢复、用户和群范围隔离、群管理员写入限制、主人范围、同主题版本替换、软删除、过期记录、敏感内容拒绝、关键词召回和提示词长度限制。

提交前运行：

```powershell
py -m pytest
py -m ruff check .
py -m ruff format --check .
py -m mypy yebot
```
