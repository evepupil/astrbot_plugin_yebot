# 身份与权限

- 模块定位：统一表达主人、当前群管理员和群员的身份及可授予能力。
- 对应代码：`yebot/domain/identity.py`、`yebot/domain/permissions.py`
- 所属里程碑：[M3](../roadmap.md#m3)
- 当前状态：进行中
- 最近更新时间：2026-08-01

## 职责与边界

定义身份来源、权限矩阵、拒绝原因和群作用域。群管理员只在当前群有效，不写入 AstrBot 全局管理员配置。

## 结构与数据流

平台事件 -> `parse_identity` -> `authorize` -> 工具网关 -> 允许、拒绝或进入后续确认流程。

## 关键决策

权限采用最小授权和显式拒绝。主人身份来自 YeBot 配置并合并 AstrBot 的 `admins_id`，群管理员身份只在当前群有效。

能力分为五类：`read`、`send_message`、`manage_group`、`manage_bot`、`external_write`。群员可读取并在当前群发消息；群管理员额外拥有当前群管理能力；主人拥有全部能力，并可把群作用域能力指向其他群。全局能力不要求群号，当前群能力会拒绝缺少群号或越过当前群的请求。

## 当前实现

`permissions.py` 提供不可变的 `CapabilityPolicy` 矩阵、`PermissionDecision` 结果和 `authorize` 入口。调用方只接收允许标志、规范化能力、角色、目标群号和稳定拒绝码，不会从权限结果中携带消息正文。

拒绝码包括 `role_denied`（角色不足）、`out_of_scope`（越过当前群）、`group_required`（当前群能力缺少群号）和 `unknown_capability`（未注册能力）。`allow` 是唯一允许结果，便于 M4 工具网关统一处理。

## 验证方式

`tests/test_permissions.py` 已覆盖三角色能力矩阵、群作用域隔离、主人跨群、缺少群号和未知能力拒绝。剩余验收需要在真实群内分别用主人、群管理员和普通群员发送受控测试消息，确认 AstrBot 事件中的角色字段与权限结果一致。

## 待扩展项
